I don't have your team's test idea format on hand, so here are the six in a common layout. Paste your template and I'll convert them.

**TI-01: Minimum length boundary (valid)**
- Input: `Abcdef12` (8 chars, 1 uppercase, 2 digits)
- Expected: Accepted

**TI-02: Below minimum length (invalid)**
- Input: `Abcde12` (7 chars)
- Expected: Rejected, length error

**TI-03: Maximum length boundary (valid)**
- Input: `Abcdefghijklmnopqr12` (20 chars)
- Expected: Accepted

**TI-04: Above maximum length (invalid)**
- Input: `Abcdefghijklmnopqrs12` (21 chars)
- Expected: Rejected, length error

**TI-05: Missing digit (invalid)**
- Input: `Abcdefghij` (10 chars, no digit)
- Expected: Rejected, digit-required error

**TI-06: Missing uppercase (invalid)**
- Input: `abcdefgh12` (10 chars, no uppercase)
- Expected: Rejected, uppercase-required error

TI-01 to TI-04 cover boundary values on length. TI-05 and TI-06 each break exactly one composition rule while keeping a valid length, so a failure points to a single cause.
